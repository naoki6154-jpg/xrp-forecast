## 計算の中身

- **同じ入力なら毎回同じ結果**：乱数の種は `config.json` の `seed`（20261107）で固定。記録には入力の指紋（`input_hash`）を残す。
- **現在値**：ドルは Binance 現物（東京の Cloud Run 経由・毎時）→ Bybit → Kraken の順。円は bitbank（1日2回）で、90分より古いときは「ドル価格×ドル円」で代わりに出し、ダッシュボード上部に「代わりの取得先」として出す。
- **変動率**：オプションの予想変動率（Deribit）が未取得のため、日足の実現変動率（EWMA と90日の平均）で代用。
- **モデルA**：`events.json` の各イベントの結果を確率で振り、影響（跳ね・じわじわ・荒れ・ドル円）を道筋に足す。12月FOMCの利上げ確率だけは Polymarket の「年末の政策金利の上限」と FRED の現在の上限から計算（市場）。他は既存の100万回試算（mc1m.py）の設定を引き継いだ「判断」で、理由は各行に記録。毎日の基本の変動は、イベントの分を差し引いて合計が実現変動率に合うように決める。裾の厚い t 分布（自由度4）、週末は変動を小さく。
- **モデルC**：方向の偏りなし（期待値ゼロ）、実現変動率、t 分布。
- **混合**：A 50%・C 50%で道筋を合わせる（合計100万本）。モデルAのイベント確率は12月FOMC以外が「判断」なので、検証（段階3）で成績が出るまでは判断の影響を抑える。設計書第6章の初期の重み（A 35%・C 20%）に戻すかは段階3で決める。
- **出力**：1日・1週間・1ヶ月・年末の、上がる確率（円・ドル）、中央値、50%・80%の範囲、信頼度。確率の幅は、モデルの答えの最小〜最大（最低±3ポイント）。
- **信頼度**：段階1は全て「低」（採点0件、判断の確率が多い）。モデルCの範囲の過去730日の的中率を参考に表示。
- 段階1で使っていないもの：モデルB（類似局面）・D（季節性）・E（機械学習）、過去事実データベース（facts/）。段階2で、別の仕組みとして足す（試運転中は混ぜない）。

## ダッシュボードのデータの書き方（どの表に何を書くか）

ダッシュボードは内蔵のデータベースを読むだけ。書き込みは `db_write`（slug `812a6935-60db-4520-a941-033b834823a7`）。

| 場所 | 書く人 | 中身 |
| --- | --- | --- |
| `runs/<run_id>_<agent>_<phase>` | 各エージェント | 稼働記録。動き始め（phase=start）と終わり（end）に1件ずつ。`agent`=main／numeric／info／verify、`status`=実行中／成功／一部失敗／失敗、`at`・`at_ms`、`duration_sec`、`ok_items`、`failed_items`、`next_at`、`note`。`dash_ops.py runlog` で作る |
| `updates/<run_id>` | メイン | 1回の更新の全データ（今の状況・予想・デリバティブ・経済・イベント・検証・取得の状況・データの新しさ・代わりの取得先）。`dash_ops.py update` で作る。上書きせず毎回追加 |
| `config/layout` | 利用者（編集ボタン）・チャット | 画面設定。欄の種類・順番・表示/非表示・開閉・中の項目（params）・単位・警告の値 |
| `layout_history/<YYYYMMDDHHMMSS>` | 画面設定を変える人 | 変更前の画面設定（`layout`）。「前の形に戻す」はいちばん新しい1件を戻して消す |
| `changelog/<YYYYMMDDHHMMSS>` | 画面設定を変える人 | 変更の履歴（`at`・`by`・`what`）。画面の一番下に出る |
| `weekly/<YYYY>-W<ww>` | ③検証（週次の振り返り） | 週ごとの振り返り（問題と頼み先・採点・稼働・データの欠け・費用・予想の変化・来週の予定・改善の候補・鍵の期限）。`engine/out/weekly_ops.json` をそのまま書く |
| `data/users/<利用者のid>/position` | 💼 保有ポジション チャット | 保有枚数 `qty`・取得額 `cost_jpy`・戦略の比較 `strategies`。本人だけが読める |

**画面設定の欄の種類**（`sections[].type`）：summary（サマリー：価格・全体の点検・4期間の上がる確率）・pipeline（エージェントの動き：取得→①→②→予想エンジン→③→メイン の6段の流れ、次の定時更新、試運転14回の成否。params に schedule・since・grace_min・trial_start・trial_days）・weekly（週次の振り返り：最新の週。params に stale_days）・status・forecast・agents・fetchers・freshness・derivatives・macro・events・news・verification・position と、汎用の number（数字）・table（表）・line（折れ線）・bar（棒グラフ）・list（一覧）。
汎用の欄は `params.path` で最新の更新（`updates`）の中の場所を指す（例 `derivatives.funding`、`history.forecast.vol_annual` で更新ごとの推移）。`fields`（列）、`fmt`（pct・yen・usd・money）、`warn`（`{key, op, value}` で赤くする）、`label`。

**チャットで画面設定を変えるとき**：`config/layout` を db_get → その内容を `layout_history/<日時>` に set → `config/layout` を `version`+1 で書く（ifVersion 付き）→ `changelog/<日時>` を追加 → handoff.md に1行追記。

鍵の一覧表は `docs/keys.md`（鍵そのものは書かない）。止まったときの対応は `engine/RUNBOOK.md` の最後の節。

画面はタブ式（2026-11-08〜、画面設定 第4版）：画面設定の `tabs`（`[{id,title}]`、この順にタブが並ぶ）と、各欄の `tab`（入れるタブの id）で決める。1つのタブに複数の欄を入れると、`sections` の順に縦に並ぶ。`visible:false` の欄は出ない。`tab` が無い欄は、その欄だけのタブになる。URLの末尾 `#<タブのid>`（例 `#market`）で開くタブを指定できる。
今のタブ：概要（overview：サマリー＝各欄の要点）・予想（forecast）・市場（market：デリバティブ・経済・今の状況の詳細）・イベント・ニュース（events）・稼働（ops：エージェントの動き・稼働の詳細・自動取得・データの新しさ）・検証（review：週次の振り返り・検証）・保有（position）。
画面の「編集」では、欄ごとに入れるタブ・並び順・表示／非表示を変えられる。

## 1.1版（2026-11-08、段階2）

- **4つのモデルの混合**：A（イベント）・B（似た過去の局面）・C（オプション）・D（季節性）を 2:2:2:1 の重みで、合計100万本。
- **モデルB**：7日・30日の騰落率、200日線からの乖離、30日の変動率、恐怖強欲指数の5つで、今と近い過去の日を60日選ぶ（互いに5日以上離す、直近60日は除く）。その後の値動きを、その日と今の変動率の比で大きさを合わせて使う。
- **モデルD**：2018年以降の各年の同じ月日から期限までの値動き。今年と4年サイクルの位置が同じ年（2018・2022年）は重み2倍。件数が少ない（8年分）。
- **モデルC**：Deribitの満期ごとの予想変動率（data/clean/xrp_atm_iv.csv）を、合計の分散でつないで1日ごとの変動にする。2日より古い・無いときは実現変動率で代用し、「代わりの取得先」に出す。モデルA・B・Dの値動きの大きさは、予想変動率（30日）と実現変動率の平均。
- **到達確率**：期限（1週間・1ヶ月・年末）までに、今の価格の±5・10・15・20・30%に一度でも届く確率（モデルA・Cの道筋から）。
- **底値の予想**：年末までの最安値の分布、下げ止まる価格帯の確率、底をつける週の割合（モデルA・Cの道筋から）。
- **要因の影響度**：イベントの結果ごとの「年末に上がっている確率」の差。
- **指標パネル**：7分野の11指標を決まった規則で追い風・中立・逆風に分ける（しきい値は判断。予想には使わない）。
- 試運転は 11/9 朝から数え直す（11/8 の2回は1.0版）。

## 1.2版（2026-11-08、段階2の仕上げ・段階3・段階4）

- **イベントは毎回組み立てる**（engine/events_sync.py）：確率と日時は📰イベント台帳（ledger/calendar.json）の「市場」「実績」を優先し、発表済みの結果（ledger/results.csv）は確定扱い。台帳にしかない経済指標（PCEなど、影響「中」以上・確率が市場か実績）は足す。
- **経済指標・FOMCの影響の大きさは実績**：facts/reactions.csv（2018年6月以降、発表日のXRPの1日の値動き）から、ふだんの日より余分に動く大きさと、予想との差の向きごとの平均の差を測り、件数が少ないほど0に寄せる（n/(n+10)）。結果ごとの値動きは「市場の織り込みを外れた分だけ動く」形（期待値0）。わかったこと：CPIの日の動きはふだんの日とほぼ同じ（中央値 2.1% 対 1.9%）、FOMCの日は大きい（2.6%）、雇用統計・PCEは余分な動きなし。以前の判断の値（CPI上振れで−3%など）より小さい。
- 判断で置いていた「下落トレンドの基調（55日−3%）」は外した。トレンドはモデルB（過去の統計）が扱う。地政学・需給・株の局面・法案・決算・日銀は「判断」のまま（確率は台帳の値）。
- **段階3：過去検証**（engine/backtest.py、2020年〜7日おき）：モデルB・C・D・混合を、その日までの情報だけで採点。結果は reports/backtest.md。モデルDのばらつきを広げた（80%範囲の的中率 65%→約80%）。
- **確率の較正**：過去検証の結果からロジスティック較正（engine/calibration.json）を作り、上がる確率を補正（補正前の値も記録）。傾きは1日 0.00・1週間 0.46・1ヶ月 0.35 で、方向を当てる実力は小さい → 確率は50%近くに寄る。
- **運用中の採点**：毎回の実行で、期限が来た予想を採点（週次の振り返りと同じ方法）。
- **信頼度を方向と範囲に分けた**：方向＝運用中の採点30件以上でブライア≦0.25なら中、100件以上で≦0.24なら高。範囲＝過去検証の80%範囲の的中率75〜85%（運用中20件以上ならその的中率70〜90%も）なら中。
- **段階4**
  - モデルE（engine/model_e.py）：勾配ブースティングで期限に上がるかを学習。前進型の検証（2021年〜、年ごと）で基準を安定して上回るまで重み0（参考表示）。2026-11-08時点では全期間で不合格。
  - 相場の状態の統計的な推定：3状態の隠れマルコフモデル（自作、乱数なし）。ルールの判定と並べて表示。
  - 戦略比較（設計書第8章）：1枚あたり・今の価格を1とした年末までの手取りの分布（今売る、保有、指値5段階、指値＋損切り、半分売り、段階的な指値）。手数料は config.json の strategy。保有枚数・取得額は画面で本人の値を掛ける（リポジトリに金額を書かない）。
  - 通知（engine/alerts.py）：前回の定時更新と比べ、節目の価格、1週間後の確率の10ポイント以上の変化、到達確率の変化、相場の状態の切り替わり、イベントの結果、資金調達率のマイナス、データの24時間以上の停止。「重要」は summary.txt の1行目に【通知】として出る。
- 定時更新の手順（RUNBOOK.md の流れ）は変わらない。追加の計算は run.py の中で行う（1回 約10秒）。

## 1.3版（2026-11-08、テクニカル指標と分岐のシナリオ）

- **テクニカル指標**（engine/technicals.py、日足 Binance XRP/USDT）：MA20・50・200、EMA12・26・50・200、MACD、RSI、ボリンジャーバンド（位置・幅）、パラボリックSAR、出来高とMAVOL20、ストキャスティクス、ADX、ATR、OBV、一目均衡表の雲、恐怖強欲指数、ナスダック・ドル指数の20日、VIX（data/raw/fred/VIXCLS.csv があれば）。各指標の今の状態と、過去に同じ状態だった日のその後7日・30日の上昇の割合（件数つき）、強気・弱気の印の合計の過去の成績を出す。
- **モデルT**：指標の状態の組み合わせが今と最も多く一致する過去の日を80日選び、その後の値動きを今の変動の大きさに合わせて使う。重み A:B:C:D:T＝2:2:2:1:2。過去検証では基準と同程度（reports/backtest.md）。
- **分岐のシナリオ（もし〜なら）**：モデルAの道筋を、影響の幅×結果の不確かさが大きい3つのイベントの結果の組み合わせで分け、組み合わせごとの確率・年末の中央値・上がる確率を出す。組み合わせを年末の中央値の順に並べ、確率の累計の下位25%・上位25%で弱気・強気・基本に分ける。全イベントの結果ごとの1週間後・1ヶ月後・年末の予想（条件付き）も出す。
