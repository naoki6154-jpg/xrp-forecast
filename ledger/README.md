## 確率の決め方（設計書 第5章の優先順位）

1. **市場**：予測市場（Polymarket など）。区分が細かいときは合計1に直してからまとめる。取得日時を必ず書く。
2. **実績**：過去事実データベース（facts/event_values.csv など）の頻度。件数も書く。
3. **判断**：どちらもないときだけ。`p_basis: "判断"` とし、`p_reason` に理由を書く。ダッシュボードでは「＊」を付ける。

市場予想（コンセンサス）は一次データがないため二次情報（経済指標カレンダー・各社の週間予定）を使い、出典URLと取得日を付ける。日時は公式の発表元（BLS・BEA・FRB・日銀・会社のIR）で確かめ、確かめられなかったものは `time_basis` にそう書く。

## 結果が出たときの手順

1. `results.csv` に1行追加（発表値・市場予想・差・区分・出典）。
2. `calendar.json` の該当イベントに結果を書き、次のイベントの確率を見直す（例：CPIの結果で12月FOMCの予測市場が動く）。
3. `python3 ledger/build.py` → 値動き（1時間・4時間・1日）が `out/results_view.json` に入る。1日分は翌日の取得後に埋まる。
4. ダッシュボードの `ledger/events`・`ledger/news` を書き直す（`out/dashboard_ledger.json` の中身）。
5. facts/ に足りない分を `to_facts/` に書く。handoff.md に1行追記。

## facts/ への受け渡し（データ基盤チャットとの取り決め案）

facts/ はデータ基盤チャットの担当なので、📰 は直接書かない。代わりに **facts/ と同じ列の CSV を `ledger/to_facts/` に置き**、データ基盤が facts-build（毎朝07:45）で取り込む。

| 置く場所 | 形 | 中身 |
| --- | --- | --- |
| `to_facts/consensus_add.csv` | `facts/consensus.csv` と同じ列 | 発表前の市場予想のうち、facts にまだない指標（CPI前月比・コアCPI前月比・PCE など） |
| `to_facts/events_manual_add.csv` | `facts/events_manual.csv` と同じ列 | 手で登録する出来事（地政学・規制・事件・決算など）。日時が確かめられないものは「日付のみ」と書く |

- 経済指標（CPI・雇用統計・PCE・FOMC）の発表値と、その後の値動き（reactions.csv）は、データ基盤の自動の仕組みがすでに作っているので重ねて書かない。
- 取り込んだ行は、データ基盤が handoff.md に「取り込み済み」と書く。📰 は取り込み済みの行を次の作業で消す（このフォルダーの中なので）。
- この形でよいかは、データ基盤チャットの返事（handoff.md）で確定させる。
